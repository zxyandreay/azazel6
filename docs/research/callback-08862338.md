The earlier callback `0x088610C4` saves `a0 + 0x5C` in `s0`. When
the ordinary BLEZ's fallthrough path updates the state, `sw a0,4(s0)`
at `0x08861110` stores `0x08862338` at the original object's
`+0x60` callback field. The BLEZ's delay slot executes **whether the
branch is taken or not**; this proves construction of the callback address,
not that the state assignment occurs on both edges. The prior bounded
native trace separately observed `0x08862338` at the dispatcher.

The existing `immediate_maps` verifier rejected all control flow between
LUI and ADDIU. The new `delay_slot_branch` witness requires an **explicit
exact instruction word**, canonical LUI / ordinary BLEZ / ADDIU adjacency,
forward in-bounds branch target beyond the address pair and the original
file-backed target. Branch-likely, altered branch bytes, unreviewed branch
forms and mismatched source locations remain rejected. Both the original
three callback targets and fail-closed JALR guard are retained.
