# Tekken 6 hybrid Android game build

This path uses pinned PortableKit's SDL Android activity, PSP interpreter,
kernel, ISO mount, FFmpeg decoders and Vulkan renderer. The Android `libmain.so`
also links one reviewed Tekken 6 USA entry function generated by
`tools/portablekit_aot.py`. The generated C++ and the user's ISO remain in
ignored `local/` paths. The APK carries no game files.

## Input admission

**VERIFIED on Windows, 2026-11-21:** the exact 855,638,016-byte ISO has SHA-256
`45e9eaa105afda7c44204909e7fa22321236c89158bd7d26b52aba2f2e0794c8`.
Its `PSP_GAME/SYSDIR/EBOOT.BIN` is an encrypted 4,158,480-byte PSP executable
with SHA-256 `254af6ab3359d290ad3ed47abf036de9aae239b1695d6c3d504bb47ef94ed6a7`.
Pinned PortableKit's installer decrypts it to a 4,158,144-byte ELF with SHA-256
`60eb876806e8625161c24e65aab6d906fc9d5740777fbcfafe7ef0fa9920c01d`.
That ELF is byte-identical to the code-bearing prefix of the original
4,158,480-byte AOT source ELF. Its final 336 bytes match the encrypted EBOOT's
final 336 bytes; combining them reproduces the AOT source SHA-256
`e0ed418952c51032796ebc54584592a9f6075495229f6d12d5065f3186bcb55f`.
The profile checks these identities before Android guest execution. An invalid
ISO, encrypted EBOOT, prepared ELF, module identity or missing native entry
stops; it does not select another game edition or log a successful import.

The tag material for PSP tag `0xD91612F0` is public, from PPSSPP's
`Core/ELF/PrxDecrypter.cpp`. The encrypted and prepared hashes still pin the
accepted content exactly. The installer copies or retains the user's ISO in
app-private storage through its file picker; no game data is packaged.

## Build and package

Use JDK 17, Android SDK platform 36/build tools 36.0.0, NDK 27.1.12297006,
the pinned local SDL3 build, Ninja and `glslangValidator` from the SDK emulator.
Generate the exact one-function corpus as described in the
[Windows hybrid checkpoint](building.md#optional-windows-hybrid-aot-checkpoint).
On Windows, bundled FFmpeg also needs Git Bash `sh`, GNU Make and a working
Windows GCC for its host build tools. The pinned FFmpeg 7.1.5 source archive is
hash-checked by PortableKit and built for Android ARM64 with ATRAC3, ATRAC3plus
and H.264 decoding.

Fetch PortableKit's pinned fallback CJK font and OFL license into ignored
`local/android-game/fonts/` before packaging. The hashes in the pinned
`packaging/sources.sh` are checked again by `android_game.py`.

```powershell
$fontDir = 'local/android-game/fonts'
New-Item -ItemType Directory -Force -Path $fontDir | Out-Null
Invoke-WebRequest 'https://raw.githubusercontent.com/notofonts/noto-cjk/Sans2.004/Sans/OTF/Japanese/NotoSansCJKjp-Regular.otf' -OutFile "$fontDir/NotoSansCJKjp-Regular.otf"
Invoke-WebRequest 'https://raw.githubusercontent.com/notofonts/noto-cjk/Sans2.004/LICENSE' -OutFile "$fontDir/NotoSansCJK-LICENSE.txt"
```

```powershell
$sdk = $env:ANDROID_HOME
$aot = (Resolve-Path local/portablekit-hybrid-entry/generated_entry.cpp).Path
$make = (Resolve-Path tools/ffmpeg_windows_make.cmd).Path
$env:PATH = 'C:/Program Files/Git/bin;' + $env:PATH
cmake -S profiles/tekken6/portablekit -B local/build/portablekit-android-hybrid -G Ninja `
  "-DCMAKE_MAKE_PROGRAM=$sdk/cmake/3.22.1/bin/ninja.exe" `
  "-DCMAKE_TOOLCHAIN_FILE=$sdk/ndk/27.1.12297006/build/cmake/android.toolchain.cmake" `
  -DANDROID_ABI=arm64-v8a -DANDROID_PLATFORM=android-29 -DANDROID_STL=c++_static `
  -DANDROID_SUPPORT_FLEXIBLE_PAGE_SIZES=ON -DCMAKE_BUILD_TYPE=Release `
  -DPORTABLEKIT_ANDROID_APP=ON -DAZAZEL6_PORTABLEKIT_RENDERER=ON `
  -DAZAZEL6_PORTABLEKIT_FFMPEG=bundled `
  "-DAZAZEL6_PORTABLEKIT_AOT_SOURCE:FILEPATH=$aot" `
  "-DSDL3_DIR=$pwd/local/android-host/native/sdl" `
  "-DPORTABLEKIT_GLSLANG=$sdk/emulator/lib64/vulkan/glslangValidator.exe" `
  -DPSPRECOMP_GENERATED_JOBS=2 "-DPORTABLEKIT_MAKE:FILEPATH=$make"
cmake --build local/build/portablekit-android-hybrid --target azazel6_portablekit_probe --parallel 2
python tools/android_game.py --sdk "$sdk" --java-home "$env:JAVA_HOME"
```

`android_game.py` requires the AOT, Vulkan, Android app and bundled FFmpeg
settings, and refuses missing native libraries or a missing native entry/counter
symbol. It checks AArch64/16 KiB ELF segments, packages SDL, FFmpeg and the
pinned fallback font with their third-party notices, creates DEX/resources with SDK tools, signs with a local
debug key, verifies the signature and 16 KiB ZIP alignment, and writes a report
next to the APK in `local/android-game/`. The report records build checks only;
device execution and game rendering need separate runtime evidence.

`ffmpeg_windows_make.cmd` repairs only paths generated in the ignored FFmpeg
build directory. Git Bash emits `/d/...` paths there; native GNU Make expects
`D:/...` paths. The bridge refuses paths outside this repository's `local/`
tree and leaves the pinned FFmpeg source and PortableKit checkout untouched.

## Runtime verification

On a compatible Android ARM64 device, install the signed debug APK, launch its
activity, select the exact user-supplied ISO, and inspect the app's log for
`exact_iso_sha256`, `prepared_elf_sha256`, `aot_source_sha256`,
`native_aot_entry_calls` and a bounded interpreter instruction count. A linked
AOT symbol or synthetic Vulkan clear is not proof of Android game execution.
Record the device ABI, APK hash, log and actual game pixels separately. An x86_64
AVD that advertises ARM64 translation does not establish physical ARM64
execution. The [Android checkpoint](../research/hybrid-android-apk-2026-11-22.md)
records an actual game opening-logo frame, one native AOT entry call and
interpreter fallback on the translated AVD. Its graphical ISO picker remains
unverified; the test placed exact validated inputs in app-private storage.
